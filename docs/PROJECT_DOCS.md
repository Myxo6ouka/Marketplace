# Анализ и архитектура

## Назначение
Маркетплейс: покупатели собирают корзину из товаров разных продавцов и оформляют один заказ; каждый продавец видит и обрабатывает свою часть (подзаказ); администратор модерирует продавцов и товары.

## Роли
- **buyer**: каталог, избранное, корзина, заказы, отзывы.
- **seller**: свой магазин (создаётся при регистрации), товары, подзаказы с переводом статусов.
- **admin**: блокировка продавцов, скрытие товаров.

## Технологии
Node.js, Express, Sequelize, PostgreSQL 18 (Docker), JWT (24 часа), bcryptjs; фронтенд на чистом JS в `public/`.

## Структура
- `server.js`: подключение роутов, раздача `public/`, единый обработчик ошибок.
- `middleware/`: `auth.js` (проверка JWT), `role.js` (проверка роли), `errors.js` (HttpError, ответы).
- `models/`: модели Sequelize и связи, таблицы создаёт `database/schema.sql`.
- `routes/`: роуты по областям (auth, products, cart, orders, seller-orders, seller-products, moderation, reviews, favorites).

## База данных
Основные таблицы: `users`, `shops` (1:1 с продавцом), `categories` (дерево), `products`, `carts` и `cart_items`, `orders`, `sub_orders` (по одному на магазин), `order_items`, `reviews`, `favorites`.
В `order_items` хранится копия названия и цены на момент заказа: изменение товара не меняет историю.

## Ключевые решения
1. **Заказ из нескольких магазинов.** Один `orders`, внутри по одному `sub_orders` на `shop_id`. Каждый продавец работает только со своим подзаказом.
2. **Целостность остатков.** `POST /orders` выполняется в одной транзакции: строки товаров блокируются (`SELECT ... FOR UPDATE`, порядок по id против взаимных блокировок), проверяются `active`, магазин и `stock`. При нехватке откат и ответ 409. Строка корзины тоже блокируется, поэтому двойной клик не создаёт два заказа.
3. **Права проверяются на сервере.** Роль берётся из JWT, `requireRole` ограничивает доступ, а владение объектом проверяется отдельно (чужой подзаказ или товар даёт 403, чужой заказ 404).
4. **Возврат остатков при отмене.** Отмена подзаказа возвращает `stock` в той же транзакции.
5. **Модерация.** `shops.is_blocked` скрывает товары магазина из каталога и запрещает их заказ; `products.status = hidden` скрывает один товар.
6. **Безопасность.** Пароли хранятся как bcrypt-хеш, роль admin недоступна через регистрацию, ошибки не раскрывают внутренности.

## Запуск с нуля на чистой копии
1. `git clone https://github.com/Myxo6ouka/Marketplace.git`, затем `cd Marketplace`.
2. `npm install`.
3. Скопировать `.env.example` в `.env` и задать `JWT_SECRET`, `DB_PASSWORD` (`DB_PORT=5433`, `DB_NAME=MR`).
4. `docker compose up -d` (схема загрузится сама при первом запуске).
5. `node scripts/seed.js` (тестовые данные).
6. `npm start`, открыть `http://localhost:3000/?mock=0`.

# Сценарий демо (5–7 минут)
1. **(0:30) Обзор.** Каталог: фильтры по цене, продавцу, категории, сортировка.
2. **(1:00) Регистрация.** Зарегистрировать нового покупателя; показать, что роль admin через регистрацию недоступна.
3. **(1:30) Корзина и заказ.** Добавить товар TechMart и товар «Всё для дома», оформить заказ. В «Моих заказах» виден один заказ с двумя подзаказами.
4. **(1:00) Склад.** Заказать «Ноутбук Air 13» (остаток 1) двумя покупателями: второй получает отказ 409, остатки не ломаются.
5. **(1:30) Продавец.** Войти как `seller1@test.ru`: видны только свои подзаказы; перевести `new → confirmed → shipped → completed`. Показать, что нельзя перескочить статус. Отменить другой подзаказ и показать возврат остатка.
6. **(1:00) Администратор.** Войти как `admin@test.ru`: заблокировать магазин (товары пропали из каталога), скрыть один товар.
7. **(0:30) Отзыв.** Покупатель оставляет отзыв на товар из выполненного заказа.
8. **(0:30) Итоги.** Что сделано, что можно улучшить.
