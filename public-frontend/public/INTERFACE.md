# Интерфейс

Фронтенд реализован на HTML, CSS и JavaScript без фреймворков. Используется один index.html: экраны переключаются по hash-маршрутам без перезагрузки страницы. Общие элементы — шапка, навигация по роли, подвал, уведомления и диалоговые формы.

## Структура
- index.html — основная страница.
- css/style.css — оформление и адаптивные правила.
- js/api.js — запросы к http://localhost:3000/api, Bearer-токен, обработка {data}/{error}, централизованный выход при 401.
- js/app.js — маршрутизация, экраны и события интерфейса.
- js/mock.js — локальная заглушка API; данные сохраняются в localStorage.
- img/p1.png ... img/p30.png — существующие локальные изображения пользователя, в обновление не включены.

Токен и роль сохраняются в localStorage. При выходе они очищаются. Видимость пунктов меню и доступность страниц зависят от роли. Проверки фронтенда не заменяют авторизацию на сервере.

## Экраны
Покупатель: регистрация и вход, каталог с деревом категорий, поиском, фильтрами по цене и продавцу, сортировкой и пагинацией; карточка товара; корзина с группировкой по магазинам; оформление с текстовым адресом и оплатой при получении; история заказов с подзаказами.
Продавец: таблица своих товаров, добавление, изменение и удаление; подзаказы со сменой статуса.
Администратор: блокировка продавцов, скрытие и восстановление товаров, создание, изменение и удаление категорий.
Статусы: Новый, Подтверждён, Отправлен, Выполнен, Отменён.

## Обработка состояний
При загрузке экрана отображается индикатор. Пустые списки содержат пояснение. Ошибки загрузки отображаются с кнопкой повторного запроса; ошибки форм — возле формы. Уведомления подтверждают действия.

## Совместимость с API
Сохранён контракт исходной версии: POST /login, /register; GET /me, /categories, /sellers, /sellers/:id, /products, /products/:id; GET /cart, POST /cart/items, PATCH/DELETE /cart/items/:id; GET/POST /orders; GET/POST /seller/products, PUT/DELETE /seller/products/:id; GET /seller/orders, PATCH /seller/orders/:id/status; GET /admin/sellers, PATCH /admin/sellers/:id/block, PATCH /admin/products/:id/hide; POST /admin/categories, PUT/DELETE /admin/categories/:id.
Список продавцов GET /sellers — новый маршрут, возвращает массив {id,name} в {data}. Админ получает товары через /products?includeHidden=1. Сервер обязан проверять роль перед выдачей скрытых товаров.
Если фронтенд и бэкенд запущены на разных портах, настройка CORS выполняется на бэкенде.

## Проверки
Выполнена проверка синтаксиса трёх JS-файлов через node --check. Автоматически проверена заглушка: вход трёх ролей, каталог, фильтр продавца, корзина, создание заказа, смена статуса подзаказа, запрет доступа заблокированному продавцу.
Добавлены CSS-правила для узких экранов, включая форму оформления. Визуальная проверка в Chrome и Firefox и на ширине 360 px в этой среде не выполнялась и остаётся обязательной перед сдачей.
